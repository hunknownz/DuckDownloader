# 图文来源验收

初次验收：2026-11-02；公众号下载复验：2026-11-03。项目已统一命名为 DuckDownloader；包名、CLI 和仓库自带 skill 使用 `duckdownloader`。飞书初次记录来自改名前的实现；公众号的新记录使用当前名称与共享内容结构/A4 排版流水线。

## 飞书 docx

使用用户提供的获授权文档，在 macOS ARM64、Camoufox 156.0.1-beta.36 上完成手动登录、会话保存、无界面采集和正式 CLI 下载。最终 PDF 为 42 页 A4，48 个目录章节、48 张本地图片全部保留；清单无警告，图片字节数和 SHA-256 校验通过。章节与前次采集结果一致。

PDF 的全部正文、48 个标题及末尾内容通过独立文字检查，另检查整份缩略图与重点页面。macOS Quartz 对部分汉字输出了外观相同的 CJK 部首码位，例如“页”被提取为“⻚”；文字对照需先做 NFKC 和已知部首归一化，不能声称所有字符都能原样复制或精确检索。HTML 与 Markdown 保留原 Unicode 正文。

真实文档、登录数据、PDF、资源、截图和检查报告仅保存在本地忽略目录，不提交 Git。Lark 租户、复杂块、wiki、表格、多维表格、嵌入媒体以及 Windows/Linux 上这两种新来源的真实下载尚未验收。Scribd 原有的平台证据见其他验收文档。

## 微信公众号（2026-11-03）

当前 `canDownload: true`。在 macOS ARM64 上，通过官方 Camoufox TypeScript SDK 的独立公众号 profile 完成两种真实样例：

- 既有获授权图文样例：4 张配图全部保存，资源字节数与 SHA-256 校验通过，生成 4 页 A4 PDF；清单无警告。
- 用户指定的文字消息：正式 CLI 退出码 0，生成 2 页 A4 PDF；正文无配图，保留 3 个原文链接及末尾内容，清单无警告。PDF 内的 emoji 可能作为图片绘制，不属于正文配图。

修复文字消息没有独立标题节点时将整篇正文当作标题的问题：用首行作为阅读标题，按空行重建段落，排除正文容器中的地点、发布时间和打赏控件。完整的首行内容移到标题；超长首行仅截短标题，保留正文。标准图文仍使用文章标题，并对所有正文图片执行完整性检查。

两份样例均独立检查全文、A4 页框、首尾内容与全部配图，并逐页渲染查看。macOS Quartz 的兼容字符仍需归一化：除 CJK 部首外，连续两个破折号可能映射为 U+2E3A 双倍破折号，列表项目符号由排版器生成；不能据此声称所有字符都能按源码逐字复制。

2026-11-02 的图片 TLS 连接失败是当时的网络结果；本次同一样例的 4 张图片已全部请求成功，没有关闭 TLS 校验、忽略图片、切换浏览器或绕过访问验证。成功后按清单归属清理本次中间 HTML、内容结构、图片和检查渲染图，仅交付用户指定 PDF；原有 partial 归档不属于本次清理范围。

此记录不证明所有公众号页面、嵌入媒体或 Windows/Linux 上的公众号下载均已通过真实验收。未支持媒体、缺图和访问验证仍明确失败并保留 partial 资料。

## 测试边界

离线测试覆盖来源路由、参数传递、明确拒绝、滚动脚本、图片域名/重定向约束、隐藏脚本清除、部分结果保留、错误日志不携带请求头，以及失败时保留既有 PDF。本地 Camoufox 测试覆盖多页图文打印、字体和 A4 页框；这些测试不能代替其他文档的真实授权验收。
